# Subus: быстрое добавление карт и категорий, любой цвет категории

Дата: 2026-10-21
Статус: черновик на ревью
Основа: `2026-10-20-subus-v1-design.md` (v1, слита в `develop`).

## 1. Цель

Заводить подписку, не прерываясь. Если нужной карты или категории ещё нет, их можно создать прямо из формы подписки. Карта добавляется выбором из сохранённых в системе карт, без ручного набора «••». У категории может быть любой цвет.

**Что сказал пользователь:**

- Неудобно сначала заводить категорию или карту в настройках, а уже потом подписку.
- Нужно больше цветов категорий, причём именно возможность выбрать любой цвет.
- Добавление карты должно быть удобнее, в идеале из системного хранилища карт.

**Критерии успеха:**

- Новую категорию или карту можно создать, не закрывая форму подписки. После создания она сразу выбрана в подписке, а остальные введённые данные не теряются.
- В поле «Номер карты» macOS предлагает сохранённые карты (AutoFill). После выбора карты в Subus остаются только последние 4 цифры и платёжная система. Полный номер нигде не сохраняется: ни в файле данных, ни в логах, ни в истории отмены.
- Цвет категории — любой. На шкале каждой темы линия читается с контрастом не ниже 3:1, при этом выбранный тон сохраняется.
- Файлы данных и экспорты v1 открываются без изменений. CSV не меняется.

**Ограничение платформы.** Сторонние приложения не могут читать список карт из Wallet, Safari или Связки ключей. С macOS 14 текстовое поле с типом содержимого `NSTextContentType.creditCardNumber` получает от системы AutoFill: macOS сама показывает сохранённые карты, а приложение получает только ту, которую выбрал пользователь. Название банка система не передаёт, поэтому пользователь вводит его сам.

**Вне объёма:**

- определение банка по BIN (нужна внешняя база);
- хранение срока действия и имени держателя карты;
- цвет у способов оплаты (в UI они нейтральные, см. поправку 18 контракта);
- произвольный цвет плиток-монограмм.

## 2. Модель данных (SubusCore)

### 2.1. `RGBColor`

`RGBColor` — новый тип в `Model/`. Это три компонента sRGB по 0…255, `Hashable`, `Codable`, `Sendable`.

- В JSON кодируется строкой `"#RRGGBB"` (верхний регистр).
- Декодирование принимает `#RRGGBB` и `RRGGBB` в любом регистре. Любая другая строка — ошибка декодирования поля. Обработку этой ошибки описывает §2.2.

### 2.2. `Category.customColor`

`Category` получает поле `customColor: RGBColor?`.

- Если оно задано, линия категории рисуется этим цветом.
- Если нет, используется пресет `colorIndex`, как в v1.
- `colorIndex` остаётся обязательным и при выборе своего цвета не сбрасывается. Он нужен как запасной цвет для старых версий Subus, которые не знают `customColor`.
- У `Category` появляется собственный `init(from:)`. `customColor` читается как `(try? c.decodeIfPresent(RGBColor.self, forKey: .customColor)) ?? nil`: некорректное значение не ломает файл, поле становится `nil`, и категория получает свой пресет. Остальные поля декодируются как в v1. `sanitized()` поле не трогает.
- `Library.currentSchemaVersion` остаётся `1`. Изменение аддитивное: v1 игнорирует неизвестный ключ.

`Category` получает вычисляемое свойство `color: CategoryColor`:

```swift
public enum CategoryColor: Hashable, Sendable {
    case preset(Int)        // 0..<Category.paletteCount
    case custom(RGBColor)
}
```

Равенство `CategoryColor` используется там, где v1 сравнивал индексы, например в капсуле пересадки на обзорной линии: она окрашивается общим цветом, только если цвет у всех станций одинаковый.

### 2.3. Подгонка контраста: `LineContrast`

`LineContrast` — новый файл в `Presentation/`, чистая функция:

```swift
public enum LineContrast {
    /// The colour moved in OKLCH lightness only, the hue kept, until it reaches `minimum` against `ground`.
    public static func adjusted(_ color: RGBColor, against ground: RGBColor, minimum: Double = 3.0) -> RGBColor
}
```

Как работает:

1. Если контраст по WCAG 2.x уже не ниже `minimum`, цвет возвращается без изменений.
2. Иначе светлота (L в OKLCH) двигается от фона: темнее на светлом фоне, светлее на тёмном. Нужная светлота ищется бинарным поиском (≤ 24 шага).
3. Тон (hue) сохраняется. Насыщенность (chroma) уменьшается только тогда, когда цвет выходит за пределы sRGB.
4. Если `minimum` недостижим, возвращается крайняя точка: чёрный или белый того же тона, контраст у них максимальный.

Опорные фоны те же, что в DESIGN.md: `#F6F6F3` для светлой темы и `#1C1C1E` для тёмной. Гарантия такая же, как у пресетов: контраст ≥ 3:1 измеряется против этих опорных фонов. Реальный фон `NSPopover` системный (стекло, вибрация) и может слегка отличаться; DESIGN.md формулирует это так же для всей палитры. Пресеты через подгонку не проходят, их контраст уже проверен.

### 2.4. Карта: `CardNumber` и `PaymentLabel.compose`

`CardNumber` — новый файл в `Presentation/`, чистые функции.

```swift
public enum CardNetwork: String, Sendable { case visa, mastercard, mir, amex, unionPay, jcb }

public enum CardNumber {
    /// Last four digits and network of a full number (12–19 digits, spaces and dashes ignored);
    /// nil when the text is not a full number.
    public static func summary(of text: String) -> (last4: String, network: CardNetwork?)?
    public static func network(ofDigits digits: String) -> CardNetwork?
}
```

Префиксы (IIN):

| Платёжная система | Префиксы |
|---|---|
| Мир | 2200–2204 |
| Mastercard | 51–55, 2221–2720 |
| Visa | 4 |
| Amex | 34, 37 |
| UnionPay | 62 |
| JCB | 3528–3589 |

Мир проверяется раньше Mastercard. Остальные номера дают `nil`. Алгоритм Луна не проверяется: AutoFill подставляет настоящие номера, а ошибку ручного ввода всё равно не поймать по одним последним 4 цифрам.

`PaymentLabel.compose(bank:last4:network:) -> String` собирает подпись:

- `"Т-Банк •• 4242"`, если есть банк и цифры;
- `"Т-Банк"`, если есть только банк;
- `"Visa •• 4242"`, если банка нет, но известна система;
- `"•• 4242"`, если есть только цифры.

Названия систем — латиницей, кроме «Мир» («Мир» / «Mir» по локали). Для форм с банком или системой `PaymentLabel.split` возвращает (банк или систему, `"•• 4242"`). Для формы `"•• 4242"` без названия `split` по правилам v1 возвращает подпись целиком и `nil`. Оба результата проверяются тестом.

`CardFieldParser` — чистая логика поля номера из §3.3, вынесена в ядро ради тестов:

```swift
public struct CardFieldState: Equatable, Sendable { public var text: String; public var last4: String?; public var network: CardNetwork? }
public enum CardFieldParser {
    /// One edit: `old` → `newText`. A jump of ≥ 8 characters with a full number is parsed at once.
    public static func edited(_ old: CardFieldState, to newText: String) -> CardFieldState
    /// Editing ended: a full number still in the text is parsed; otherwise the state stands.
    public static func ended(_ state: CardFieldState) -> CardFieldState
}
```

Модель `PaymentMethod` не меняется. Подпись остаётся свободным текстом, как в v1.

## 3. Интерфейс (App)

### 3.1. Создание из формы подписки

- В конце пикеров «Категория» и «Способ оплаты» в `EditorView` появляются разделитель и пункты «Новая категория…» и «Новая карта…».
- Пикер работает не напрямую с `UUID?`, а с отдельным UI-выбором `enum PickerChoice: Hashable { case none, existing(UUID), create }`. Его `Binding` читает `draft`. При записи `.none` или `.existing` меняется `draft`, а `.create` черновик не меняет и только открывает лист (`.sheet`) поверх окна формы. Поэтому после «Отмены» в пикере остаётся прежний выбор, и пункт «Новая…» можно выбрать снова.
- По «Добавить» лист:
  1. записывает новую категорию или способ оплаты через `model.editLibrary`;
  2. только если запись удалась, выставляет `draft.categoryID` или `draft.paymentMethodID` на новую запись и закрывается;
  3. если `editLibrary` вернул ошибку, лист остаётся открытым и показывает её системным красным под полями, а черновик не меняется.
- «Отмена» закрывает лист без изменений.
- Черновик формы ничего не теряет. Новая запись сохраняется сразу, даже если подписку потом не сохранят. Это обычная запись, её можно удалить в настройках.

### 3.2. Лист «Новая категория»

- Поле «Название», с фокусом при открытии.
- Строка из 8 пресетов и кнопка «Другой цвет…» (`ColorPicker(supportsOpacity: false)`, системная палитра macOS). Выбранный `Color` переводится в `NSColor`, затем в `.sRGB` (`usingColorSpace`); компоненты обрезаются до 0…1 и округляются до 8 бит. Предпросмотр и сохранение используют уже округлённое значение.
- Предпросмотр: кольцо-станция в итоговом цвете для текущей темы, то есть после подгонки из §2.3.
- Кнопка «Добавить» неактивна при пустом названии. Если категория с таким названием (без учёта регистра) уже есть, вместо создания выбирается существующая.
- По умолчанию выбран следующий свободный пресет: `categories.count % paletteCount`, как в v1.

### 3.3. Лист «Новая карта»

Поля:

1. **«Номер карты»** — `NSViewRepresentable` над `NSTextField` с `contentType = .creditCardNumber`.
   - **Когда разбирается номер.** Полный номер (`CardNumber.summary` не `nil`) разбирается в двух случаях:
     - одно изменение текста добавило сразу ≥ 8 символов (так работают AutoFill и вставка);
     - редактирование закончилось (Return, уход фокуса, закрытие листа).

     Поэтому ручной набор не обрывается на 12-й цифре.
   - **Что происходит после разбора.** Поле запоминает `last4` и систему и заменяет текст на `"•• 4242"`. Текст в таком виде (`••`, пробел, 4 цифры) читается обратно как тот же `last4` с прежней системой, поэтому повторный вызов делегата после замены ничего не ломает.
   - **Ручной ввод и сброс.** Ровно 4 цифры — это `last4` без системы. Любая правка текста, после которой он не совпадает ни с `"•• dddd"`, ни с 4 цифрами, сбрасывает `last4` и систему. Если после окончания редактирования текст по-прежнему не распознан, показывается подсказка «Введите последние 4 цифры или выберите карту».
   - **Приватность.** Поле — подкласс `NSTextField`:
     - в `becomeFirstResponder` у общего field editor окна (`currentEditor() as? NSTextView`) выключается `allowsUndo` до того, как в поле что-то попадёт;
     - при замене текста меняется и строка field editor, а его undo-действия для этого поля снимаются (`undoManager?.removeAllActions(withTarget:)`);
     - когда лист закрывается, редактирование завершается, и строка field editor очищается.
   - **Что видит SwiftUI.** В SwiftUI-биндинги поле отдаёт только `last4` и систему, полный номер наружу не передаётся. Значение для VoiceOver после разбора — маска `"•• 4242"`. Содержимое поля не логируется и не попадает в тексты ошибок.
2. **«Банк или сервис»** — свободный текст, необязательно.
3. **«Подпись»** — только для чтения, результат `PaymentLabel.compose`. Пример: «Т-Банк •• 4242».

Под полем номера — подсказка: «macOS предложит сохранённые карты. Subus хранит только последние 4 цифры».

«Добавить» активна, если подпись не пуста. Если способ оплаты с такой подписью уже есть, выбирается существующий.

Будет ли системный список карт показан в окне Subus, зависит от macOS и от того, есть ли сохранённые карты. Это проверяется вручную (§5). Без AutoFill лист работает с ручным вводом 4 цифр.

### 3.4. Настройки

- **Импорт.** При импорте JSON в режиме «Добавить» категория, совпавшая с локальной по ID или названию, остаётся локальной целиком, вместе с цветом, как в v1. Новые категории приходят со своим `customColor`. В режиме «Заменить» цвета берутся из файла. CSV цвет не переносит: категории из CSV, как и в v1, получают пресеты по порядку.
- **«Категории».** В поповере цвета у строки к 8 пресетам добавляется «Другой цвет…» (`ColorPicker`). Выбор пресета сбрасывает `customColor`, выбор своего цвета задаёт его. Название цвета в подсказке и VoiceOver для своего цвета — «Свой цвет».
- **«Новая категория»** и **«Новый способ оплаты»** открывают те же листы, что и форма (§3.2, §3.3), вместо строки с текстом по умолчанию.
- Переименование в строке списка остаётся как в v1.

### 3.5. Цвет линий

- Вместо `lineIndex: Int?` получают `lineColor: CategoryColor?`:
  - `UpcomingItem`, `AllItem`, `SpendingBar` и сборка `SpendingTab.categoryBars`;
  - `ChargeStop`, `StationAnchor`, `StationRing`, `StripCanvas.stations`;
  - кластеры `OverviewLine`;
  - `NamedColorItem`, `onRecolor` и `SwatchButton` в `NamedColorList`.
- `TrialTag` вызывает `LinePalette.line(.preset(LinePalette.violet), scheme)`.
- Индексы монограмм и способов оплаты остаются `Int`.
- `LinePalette.line(_ color: CategoryColor?, _ scheme:)` устроена так:
  - пресет — как в v1;
  - свой цвет — `LineContrast.adjusted` против фона текущей темы;
  - `nil` — цвет рельса.
- Результат подгонки кэшируется по паре (цвет, тема).
- Увеличенный контраст (Increase Contrast) по-прежнему только утолщает линии.

## 4. Дизайн-система

Обновляются DESIGN.md, `.impeccable/design.json` и поправка 20 к контракту панели. Суть поправки:

- Категория может иметь свой цвет. Контраст линии ≥ 3:1 обеспечивается подгонкой светлоты, тон не меняется.
- Правило «оранжевый — только акцент» для своих цветов не применяется принудительно: пользователь вправе выбрать оранжевый. Пресеты оранжевый по-прежнему не содержат.

## 5. Тестирование

**SubusCore (Swift Testing):**

- `RGBColor`: кодирование и декодирование, регистр, строка без `#`, отказ на мусоре.
- `Category`: `customColor` отсутствует, задан или некорректен (в последнем случае `nil`, остальной файл читается). Старый JSON v1 декодируется. Круговой проход через `Transfer` JSON сохраняет цвет. Импорт в режиме «Добавить» с совпадением по ID и по названию оставляет локальный цвет, в режиме «Заменить» берёт цвет из файла.
- `LineContrast`: цвет с достаточным контрастом не меняется. Светлый жёлтый на светлом фоне темнеет до ≥ 3:1, тёмно-синий на тёмном фоне светлеет до ≥ 3:1, оттенок отклоняется не больше чем на 2°. Недостижимый `minimum` (например, 25) даёт крайнюю точку: чёрный на светлом фоне, белый на тёмном.
- Разбор поля номера (чистая логика вынесена в `CardFieldParser` в SubusCore): постепенный набор 12+ цифр не разбирается до конца редактирования; вставка за раз разбирается сразу; маска `"•• 4242"` распознаётся обратно; правка сбрасывает `last4`.
- `CardNumber`: каждая система по префиксу, граничные значения (2221, 2720, 2200, 2204, 3528, 3589), пробелы и дефисы, слишком короткий или длинный номер, нецифры.
- `PaymentLabel.compose`: все четыре формы и результат `split` для каждой (§2.4).

**Приложение:**

- Снимки `make snapshots`:
  - лист «Новая категория» с пресетом и со своим цветом;
  - лист «Новая карта» пустой и после выбора карты;
  - пикер формы с пунктами создания;
  - панель с категорией своего цвета, в светлой и тёмной теме.
- Ручная проверка пользователем: показывает ли поле «Номер карты» системный список сохранённых карт и что остаётся в поле после выбора.

**Ревью:** Codex на каждом этапе (`codex exec -s read-only`).

## 6. Совместимость и риски

- **Старая версия Subus и новый файл.** Ключ `customColor` игнорируется, категория показывается своим пресетом. Данные не теряются, пока файл не перезапишет старая версия: при сохранении v1 неизвестное поле пропадёт. Это допустимо: обратной совместимости по записи v1 не обещала.
- **Полный номер карты.** Он существует только в строке поля и field editor, пока не будет разобран (§3.3). Он не пишется в файл, логи и биндинги, история отмены для поля выключена до ввода, а field editor очищается при закрытии листа. Полностью исключить копию в памяти процесса AppKit нельзя, но она не сохраняется и не покидает процесс.
- **AutoFill недоступен** (нет сохранённых карт, выключен в настройках, система не показывает его в этом поле). Ручной ввод работает.
