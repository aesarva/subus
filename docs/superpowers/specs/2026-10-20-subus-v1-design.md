# Subus — версия 1

Дата: 2026-10-20
Статус: черновик на ревью

## 1. Цель и контекст

Subus — нативное приложение для строки меню macOS, которое ведёт учёт подписок пользователя: что, сколько и когда спишется, и напоминает заранее — до списания и до конца пробного периода.

**Аудитория:** автор, затем публичное распространение (GitHub/DMG, в перспективе App Store). Developer ID в процессе оформления — архитектура должна позволить перейти на подпись и нотаризацию без переделки.

**Монетизация:** v1 бесплатная. Архитектура не закрывает дверь для будущей Pro-версии, но StoreKit в v1 нет.

**Критерии успеха v1:**
- Подписку можно добавить за ~30 секунд: название, цена, валюта, период, дата первого списания.
- Уведомления приходят за 5, 3 и 1 день (настраиваемо) до каждого списания и до конца каждого пробного периода — в том числе когда приложение не запущено, в пределах горизонта планирования.
- Итог в месяц/год в основной валюте с учётом подписок в других валютах по курсу ЦБ; без сети работает на кэше.
- Данные пользователя не теряются: атомарная запись, бэкап, восстановление при повреждении файла.
- Приложение ходит в сеть только за курсами ЦБ (cbr.ru) и — по явному действию пользователя — за иконкой сайта: к сайту подписки и к тем HTTPS-адресам, на которые он ссылается или перенаправляет для иконки (например, CDN).

**Вне v1:** iCloud-синхронизация, виджеты, горячая клавиша, каталог популярных сервисов (кандидат на v1.1), ручной журнал оплат, индивидуальные дни напоминаний для подписки, общие подписки, StoreKit.

- App Sandbox включён. Entitlements: `com.apple.security.network.client`, `com.apple.security.files.user-selected.read-write`. Hardened runtime включён.

- Локализация: английский (исходный) и русский, String Catalog `Localizable.xcstrings`, `String(localized:)`. Переключатель языка в настройках: Системный / Русский / English (пишет `AppleLanguages` в домен приложения, применяется после перезапуска) — как в Lidless.

## 4. Модель данных

### 4.1. Вспомогательные типы

- **`LocalDate`** — календарная дата (год, месяц, день) без времени и часового пояса. Все даты списаний, старта, пробного периода и окончания хранятся как `LocalDate`, чтобы смена часового пояса или перевод часов не сдвигали списание на соседний день. Кодируется в JSON как строка `"YYYY-MM-DD"`.
- **`Money`** — `amount: Decimal` + `currency: String` (ISO 4217). Никаких `Double` для сумм.
- **`BillingCycle`** — `count: Int` (≥ 1) + `unit: day | week | month | year`. Примеры: 1 месяц, 1 год, 3 месяца, 28 дней.

### 4.2. `Subscription`

| Поле | Тип | Смысл |
|---|---|---|
| `id` | `UUID` | |
| `name` | `String` | непустое |
| `logo` | `Logo` | `.monogram(colorIndex: Int?)` / `.image(fileName)` / `.siteIcon(fileName)`; файлы — `Application Support/Subus/Logos/<id>.png`, 128×128 |
| `price` | `Money` | текущая цена |
| `cycle` | `BillingCycle` | |
| `startDate` | `LocalDate` | дата первого списания — якорь расписания |
| `endDate` | `LocalDate?` | после неё списаний нет (отменена «действует до», фиксированный срок) |
| `trialEndDate` | `LocalDate?` | пробный период: до этой даты списаний нет, первое платное списание — в эту дату |
| `isActive` | `Bool` | неактивная не считается в итогах, не напоминает, лежит в секции «Неактивные» |
| `categoryID` | `UUID?` | |
| `paymentMethodID` | `UUID?` | |
| `websiteURL` | `URL?` | для загрузки иконки |
| `manageURL` | `URL?` | «Управлять / отменить» |
| `priceHistory` | `[PriceChange]` | `effectiveFrom: LocalDate`, `price: Money`; запись добавляется при изменении цены, отсортировано по дате |
| `notificationsEnabled` | `Bool` | по умолчанию `true` |
| `notes` | `String` | |
| `createdAt` | `Date` | |

**Пробный период и якорь:** если `trialEndDate` задан, расписание строится от `trialEndDate` (первое платное списание), а `startDate` хранит дату начала пользования. Если не задан — от `startDate`.

**Завершившаяся подписка:** если `endDate` в прошлом, подписка показывается как «Завершилась», ведёт себя как неактивная (в итогах не считается, не напоминает), но `isActive` не меняется автоматически.

**Возобновление:** при переключении неактивной подписки в активную расписание продолжается от исходного якоря — ничего вводить заново не нужно.

**Инварианты** (проверяются после каждого чтения файла данных и импорта): период — 1…999 единиц; id подписок, категорий и способов оплаты уникальны (дубликат получает новый id); ссылки на несуществующую категорию или способ оплаты обнуляются; имя файла логотипа — только `[A-Za-z0-9-]+.png` (иначе — монограмма), файлы логотипов не выходят за пределы `Logos/`.

### 4.3. `Category`, `PaymentMethod`

- `Category`: `id`, `name`, `colorIndex` (индекс в палитре из DESIGN.md). При первом запуске создаются стандартные: Софт, Развлечения, Музыка, Облако, Работа, Прочее (локализованные названия на момент создания). Можно переименовывать, удалять (подписки теряют категорию), добавлять.
- `PaymentMethod`: `id`, `label` (свободный текст, например «Т-Банк •• 4242»), `colorIndex`. Номера карт не запрашиваются и не хранятся.

### 4.4. `AppSettings` (UserDefaults, ключ `settings.v1`, JSON)

- `baseCurrency: String` — по умолчанию из `Locale.current.currency`, фолбэк `USD`.
- `reminderDays: [Int]` — по умолчанию `[5, 3, 1]`; допустимы 0…30, уникальные, сортируются по убыванию.
- `reminderTime: (hour, minute)` — по умолчанию 10:00 локального времени.
- `showMenuBarCounter: Bool` — по умолчанию `true`.
- `language: system | ru | en`.
- Автозапуск не хранится в настройках — источник истины `SMAppService.mainApp.status`.

Декодирование терпимое: неизвестные поля игнорируются, отсутствующие/некорректные — значения по умолчанию. `SettingsStorage` — протокол; в тестах in-memory.

### 4.5. Файл данных

`Application Support/Subus/subscriptions.json` (в контейнере песочницы):

```json
{ "schemaVersion": 1, "subscriptions": [...], "categories": [...], "paymentMethods": [...] }
```

## 5. Расчёты (`SubusCore/Schedule`, `Presentation`)

### 5.1. `BillingSchedule`

- `chargeDate(n)` = якорь + n·cycle, вычисляется **от якоря**, а не от предыдущей даты. Для месяцев/лет день месяца ограничивается длиной месяца: якорь 31 января → 28/29 февраля → 31 марта → 30 апреля. Якорь 29 февраля с годовым циклом → 28 февраля в невисокосные годы.
- `nextCharge(onOrAfter: LocalDate) -> LocalDate?` — `nil`, если подписка неактивна, завершилась, или следующая дата позже `endDate`.
- `charges(in: ClosedRange<LocalDate>) -> [Charge]` — `Charge`: дата, сумма по `priceHistory` на эту дату (последняя запись с `effectiveFrom ≤ date`, иначе текущая `price`), признак «первое списание после пробного периода».
- Прошлые списания (для карточки и «Трат») восстанавливаются из расписания и истории цен.

### 5.2. `CostNormalizer`

- Стоимость в месяц: месяцы — `price / count`; годы — `price / (12·count)`; недели — `price · 52 / (12·count)`; дни — `price · 365 / (12·count)`. В год — ×12 от месячной. Арифметика в `Decimal`, округление только при отображении.
- Пробный период, ещё не закончившийся, в итогах учитывается по будущей цене с пометкой (итог показывает «будущие» обязательства, а не только текущие).

### 5.3. Итоги и группировки

- Итог в месяц/год — сумма по активным незавершившимся подпискам, сконвертированная в основную валюту (§7). Подписки в валюте без курса не входят в сумму; итог помечается «без учёта N подписок».
- Разбивка по категориям и по способам оплаты — то же, сгруппированное; «Без категории» / «Без способа оплаты» — отдельными строками.
- «Подорожали за год»: подписки, у которых в `priceHistory` есть запись за последние 365 дней с ценой выше предыдущей (в той же валюте).
- Группировка ближайших списаний: «Сегодня и завтра», «На этой неделе» (до конца текущей недели по `Calendar.current`), «В этом месяце», «Позже» (до 60 дней).

## 6. Уведомления

### 6.1. Виды

- **Списание:** заголовок — название подписки; текст — «Списание через N дн. · сумма · способ оплаты» (способ — если задан). Плюрализация через String Catalog.
- **Конец пробного периода:** «Пробный период заканчивается через N дн., затем сумма / период».
- День списания (0) — только если пользователь добавил 0 в `reminderDays`.

### 6.2. Действия (категории `UNNotificationCategory`)

- «Управлять подпиской» — открывает `manageURL` (действие добавляется, только если ссылка задана: две категории — с ссылкой и без).
- Клик по уведомлению — открывает панель с карточкой этой подписки.
- `willPresent` → `[.banner, .list, .sound]`, чтобы уведомления показывались и при активном приложении.

### 6.3. `ReminderPlanner` (чистая функция)

`plan(subscriptions, settings, now: Date, calendar, justSaved: Set<UUID>) -> [PlannedReminder]`

- Для каждой активной незавершившейся подписки с `notificationsEnabled` берёт списания в горизонте 60 дней, для каждого `d ∈ reminderDays` — момент «дата списания − d дней, `reminderTime`».
- Моменты в прошлом отбрасываются. Исключение — «догоняющее» напоминание: только для подписок из `justSaved` (созданы или изменены в этом сохранении), если для ближайшего списания все его моменты уже прошли, а само списание ещё впереди (или сегодня) — ставится одно напоминание на `now + 1 мин` с актуальным числом дней (сценарий: подписку добавили сегодня в 15:00, списание завтра). При прочих триггерах перепланирования (`justSaved` пуст) догоняющих нет — иначе каждое пробуждение Mac повторяло бы его.
- Результат сортируется по моменту и обрезается до **60** — бюджет приложения с запасом под системное ограничение числа ожидающих локальных уведомлений (~64). Ошибки постановки уведомлений логируются.
- Догоняющие напоминания из предыдущего плана, ещё не доставленные, переносятся в новый план, пока подписка живая и списание актуально — иначе перепланирование в ту же минуту (пробуждение, смена настроек) удалило бы их.
- `id` детерминированный: `"<subscriptionID>|<chargeDate>|<daysBefore>|<kind>"`.
- Текст формируется в момент планирования на текущем языке приложения.

### 6.4. `UserNotifier` (App/Services)

- `replaceAll(_ reminders)`: снимает все ожидающие уведомления Subus и ставит новые: обычные — `UNCalendarNotificationTrigger` по компонентам год/месяц/день/час/минута григорианского календаря, без повторов; догоняющие — `UNTimeIntervalNotificationTrigger` на оставшиеся секунды.
  - Amended 2026-10-21 after review: компоненты обычного триггера (эра/год/месяц/день/час/минута) берутся из системного календаря (`Calendar.current`), по которому система сопоставляет триггер, и не содержат ни календаря, ни часового пояса — это плавающее локальное время: 10:00 остаётся 10:00 после смены пояса, даже пока приложение закрыто. Прогоны `replaceAll` выполняются последовательно (цепочка задач), более новый план вытесняет незавершённый, а в конце прогона снимаются наши ожидающие запросы, которых нет в плане.
- Делегат центра уведомлений устанавливается до завершения запуска, чтобы клик по уведомлению при холодном старте открывал карточку; методы делегата — `nonisolated` с явным переходом на главный actor.
- Перепланирование вызывается из `AppModel` при: изменении данных (с `justSaved` = изменённые подписки), изменении настроек уведомлений/языка/валюты, `NSCalendarDayChanged`, `NSWorkspace.didWakeNotification`, запуске приложения.
- Защита от запуска без бандла (`Bundle.main.bundleIdentifier == nil`) — как в ochre.

### 6.5. Разрешение

- Запрашивается при первом сохранении подписки, не при запуске.
- Если отказано/выключено — в панели плашка «Уведомления выключены — Открыть настройки» (открывает системные настройки уведомлений). Статус перепроверяется при открытии панели.
- В настройках — кнопка «Тестовое уведомление».

## 7. Валюты

- **Источник:** `https://www.cbr.ru/scripts/XML_daily.asp` (без ключа). Ответ в windows-1251, десятичный разделитель — запятая, курс задан за `Nominal` единиц (например, 100 KZT). `CBRParser` возвращает `[ISO: Decimal]` — рублей за 1 единицу валюты; RUB = 1.
- **Кросс-курс:** `A→B = rub(A) / rub(B)`.
- **`RateProvider`** — протокол (`fetchRates() async throws -> RateTable`); реализация `CBRRateProvider`. Замена источника не затрагивает остальной код.
- **`RateCache`:** последняя `RateTable` с датой курса (из атрибута `Date` в XML) и временем загрузки — файл `rates.json` в Application Support.
- **Обновление:** при запуске и далее каждые 12 часов, если кэш старше 24 часов; при ошибке — повтор при следующей проверке. Таймаут запроса 10 с.
- **Отображение:** если в итогах участвовала конвертация, под итогом мелко — «Курс ЦБ на 18 окт.». Если кэша нет — конвертация не выполняется, итог только по подпискам в основной валюте + пометка «без учёта N подписок».
- **Выбор валюты в форме:** популярные сверху (RUB, USD, EUR, GBP, KZT, TRY, AMD, GEL, UAH, BYN, CNY), полный список ISO 4217 через поиск. Подписка может быть в любой ISO-валюте; если её нет в таблице ЦБ — показывается в своей валюте, в сумму не входит.

## 8. Логотипы

Приоритет отображения: своё изображение → иконка сайта → монограмма.

- **Своё изображение:** перетаскивание на поле логотипа в форме или выбор файла (`NSOpenPanel`, изображения). Масштабируется в 128×128 (aspect fill, центр), сохраняется PNG.
- **Иконка сайта:** только по кнопке «Загрузить иконку» в форме (если задан `websiteURL`). `SiteIconFetcher`: загружает HTML главной страницы → `IconHTMLParser` ищет `apple-touch-icon`, затем `<link rel="icon">` (выбор наибольшего по `sizes`, SVG пропускается) → фолбэк `/favicon.ico`. Только https, таймаут 5 с, максимум 3 редиректа, ответ не больше 2 МБ. Ошибка — подпись «Не удалось загрузить иконку» у кнопки.
- **Монограмма:** первая буква названия (графема, в верхнем регистре) на цветной подложке; цвет — `colorIndex`, если задан, иначе детерминированно по стабильному хэшу названия (не `hashValue`). Палитра — из DESIGN.md.
- Логотипы брендов в приложение не встраиваются.

## 9. Интерфейс

Визуальное направление, палитра, типографика, Liquid Glass и фолбэк для macOS 14–15 определяются через impeccable (PRODUCT.md, DESIGN.md, макеты) до начала реализации UI. Этот раздел фиксирует состав и поведение.

### 9.1. Строка меню

- Монохромный template-значок; если `showMenuBarCounter` — справа текст «Nд» (дней до ближайшего списания среди активных подписок, включая первое списание после пробного периода; без ограничения горизонтом — годовая подписка через 90 дней даёт «90д»). Нет будущих списаний — только значок. Акцент при 0–1 дне — по DESIGN.md.
- Левый клик — панель. Правый клик — меню: «Добавить подписку…», «Настройки…», «Выйти Subus».

### 9.2. Панель (~360pt шириной)

Вкладки сверху:

1. **«Скоро»** (по умолчанию): шапка — итог в месяц (крупно), в год (мельче), подпись о курсе (§7), пометка «включая N пробных периодов по будущей цене», если такие есть (§5.2). Ниже — ближайшие списания по группам (§5.3). Строка: логотип, название, «через 3 дня · 24 окт.», сумма в валюте подписки; бейдж «Пробный» для первого списания после пробного периода.
2. **«Все»:** все подписки по алфавиту, фильтр по категории, поиск (набор с клавиатуры сразу фильтрует). Внизу — свёрнутая секция «Неактивные» (неактивные и завершившиеся).
3. **«Траты»:** месячная разбивка по категориям и по способам оплаты (горизонтальные полосы, без круговых диаграмм); список «Подорожали за год».

**Карточка подписки** (push внутри панели, кнопка «Назад»): логотип, название, цена/период, следующие 3 списания, категория, способ оплаты, история цен, кнопки «Управлять подпиской ↗» (если есть `manageURL`), тумблер «Активна», «Изменить», «Удалить» (с подтверждением).

**Пустое состояние:** кнопка «Добавить первую подписку» и одна строка о назначении приложения.

**Плашки:** уведомления выключены (§6.5); данные восстановлены из бэкапа / файл повреждён (§10).

### 9.3. Окно формы (добавление/редактирование)

Отдельное `NSWindow` (не в панели — панель закрывается при потере фокуса, а выбор файла и ввод её провоцируют). Поля: название*, логотип, цена* и валюта*, период*, дата первого списания*, пробный период (переключатель + дата окончания), дата окончания, категория, способ оплаты, сайт (+ «Загрузить иконку»), ссылка управления, заметки, «Уведомлять» (переключатель). Валидация: обязательные поля, цена > 0, `trialEndDate ≥ startDate`, `endDate ≥` якоря, корректные URL (схема добавляется автоматически). Сохранение — ⌘S/Enter (кнопка всегда доступна; при ошибках валидации они показываются под полями, фокус — на первое ошибочное поле, сохранения нет), отмена — Esc. Изменение цены у существующей подписки добавляет запись в `priceHistory` с датой «сегодня» (поле даты вступления в силу — редактируемое).

### 9.4. Окно настроек (нативное, вкладки)

- **Основные:** основная валюта, автозапуск (`SMAppService.mainApp`), язык, счётчик в строке меню.
- **Уведомления:** дни напоминаний (набор чипов + добавить), время, «Тестовое уведомление», статус разрешения.
- **Категории:** список с переименованием, цветом, удалением, добавлением.
- **Способы оплаты:** то же.
- **Данные:** экспорт JSON/CSV, импорт, «Показать папку с данными».
- **О программе:** версия, лицензия GPL-3.0, ссылка на репозиторий, политика сети (§1).

### 9.5. Клавиатура

⌘N — новая подписка; ⌘, — настройки; Esc — закрыть панель/вернуться из карточки; набор текста во вкладке «Все» — поиск.

## 10. Хранение и ошибки

- **`SubscriptionStore`** — протокол (`load() throws -> Library`, `save(Library) throws`); реализация `JSONFileStore` поверх протокола файловой системы.
- **Запись:** атомарная (временный файл → замена). Перед каждой записью текущий файл копируется в `subscriptions.backup.json`. Изменение сначала записывается и только после успеха показывается в интерфейсе и перепланирует уведомления; при ошибке записи данные в памяти остаются прежними, форма не закрывается, в панели — плашка «Не удалось сохранить изменения».
- **Повреждённый файл** (невалидный JSON, `schemaVersion` новее поддерживаемой): исходный файл не перезаписывается — переименовывается в `subscriptions.corrupt-<YYYYMMDD-HHmmss>.json`; содержимое валидного бэкапа записывается обратно в основной файл (чтобы следующий запуск не начал с пустой библиотеки), в панели — плашка с кнопкой «Показать в Finder». Без валидного бэкапа — основной файл создаётся с пустой библиотекой + та же плашка.
- **Миграции:** пошаговые `v(n) → v(n+1)`, появятся с первой новой версией схемы (в v1 версия одна); декодирование терпимое (неизвестные поля игнорируются).
- **Сеть:** ошибки — в `os.Logger` (subsystem = bundle id); пользователю — только последствия (дата курса, подпись у кнопки иконки). Без модальных алертов.
- **Импорт** (`Transfer`):
  - JSON — формат файла данных целиком плюс логотипы (PNG в base64), чтобы резервная копия восстанавливалась на чистом Mac вместе с изображениями (категории и способы оплаты сопоставляются по `id`, при отсутствии — по имени). При импорте в режиме «Добавить» подписка, чей id уже есть, получает новый id и собственную копию файла логотипа.
  - CSV — колонки `name, price, currency, cycle_count, cycle_unit, start_date, end_date, trial_end_date, active, category, payment_method, website, manage_url, notes`; разделитель `,` или `;` (определяется по заголовку), кавычки по RFC 4180, даты `YYYY-MM-DD`.
  - Перед применением — предпросмотр «Найдено N подписок, M с ошибками (строки …)»; режимы «Добавить к существующим» / «Заменить все» (перед заменой — бэкап).
- **Экспорт:** JSON (полный, с логотипами, для резервной копии) и CSV (те же колонки, UTF-8 с BOM — чтобы Excel и Numbers правильно показывали кириллицу; при импорте BOM снимается). CSV не переносит историю цен, логотипы и флаг уведомлений — при импорте они получают значения по умолчанию.

## 11. Тестирование

Swift Testing (`import Testing`), только `SubusCore`, фейки для часов, ФС, сети и `SettingsStorage`.

- **BillingSchedule:** конец месяца (31.01 → 28/29.02 → 31.03 → 30.04), 29.02 с годовым циклом, циклы 28 дней / 3 месяца / год / 2 недели, пробный период (якорь), `endDate` (включительно), неактивная, завершившаяся, цена по `priceHistory` на дату.
- **LocalDate:** кодирование/декодирование, сравнение, независимость от часового пояса.
- **CostNormalizer и итоги:** все единицы цикла, смешанные валюты, валюта без курса, отсутствие кэша, точность `Decimal`.
- **ReminderPlanner:** набор дней, `reminderTime`, горизонт 60 дней, обрезка до 60 и сортировка, детерминированные id, догоняющее напоминание только для `justSaved` и не повторяется при пустом `justSaved`, `notificationsEnabled = false`, неактивные/завершившиеся, конец пробного периода.
- **CBRParser:** реальный образец XML в фикстурах (windows-1251, запятая, `Nominal`), кросс-курсы, битый XML.
- **RateCache / логика обновления:** свежесть 24 ч, работа без сети.
- **JSONFileStore:** атомарность, бэкап, повреждённый файл → corrupt + бэкап, `schemaVersion` новее, миграция.
- **SettingsStore:** терпимое декодирование, значения по умолчанию, валидация `reminderDays`.
- **Transfer:** JSON туда-обратно без потерь; CSV: кавычки, `;`/`,`, ошибки в строках, пустые необязательные поля.
- **IconHTMLParser:** выбор наибольшей иконки, относительные URL, отсутствие тегов → favicon.ico.
- **Monogram:** графемы (эмодзи, кириллица), стабильность цвета.
- **Presentation:** группировка по срокам, форматирование сумм в разных валютах и локалях, текст счётчика («3д» / «3d»), плюрализация «через N дней».

UI-тестов нет. В Debug-сборке аргумент `-Snapshots` рендерит все состояния панели, формы и пустых/ошибочных экранов в PNG (для ревью дизайна и README) — как в соседних проектах; из-за песочницы файлы пишутся во временный каталог контейнера, а `make snapshots` копирует их в `build/snapshots/`. Также `-OpenPanelOnLaunch` и `-SeedDemoData` для разработки.

Дополнительные тесты ядра (по ревью): восстановление после повреждения при двух запусках подряд; сбой записи не теряет старые данные; перенос догоняющего напоминания через перепланирование; переход на летнее/зимнее время; инварианты импорта; BOM в CSV; ограничения реального HTTP-клиента (редирект на http, лимит размера, число редиректов).

## 12. Сборка и релиз

- `project.yml` (XcodeGen): один app-таргет `Subus` + локальный пакет `SubusCore`; `SWIFT_VERSION 6.0`, deployment 14.0, `CODE_SIGN_IDENTITY "-"`, `ENABLE_APP_SANDBOX YES`, `ENABLE_HARDENED_RUNTIME YES`, `SWIFT_EMIT_LOC_STRINGS YES`, `LOCALIZATION_PREFERS_STRING_CATALOGS YES`, `CFBundleLocalizations: [en, ru]`, `MARKETING_VERSION 0.1.0`.
- **Makefile:** `test` (`swift test` в пакете + `plutil -lint`), `generate`, `build` (Debug), `run`, `app` (`scripts/build-app.sh`), `dmg` (`scripts/release.sh $(VERSION) --unsigned`). Makefile и скрипты выставляют `DEVELOPER_DIR` на Xcode.app (системный `xcode-select` сейчас указывает на Command Line Tools).
- **`scripts/build-app.sh`:** universal Release, `CFBundleVersion = git rev-list --count HEAD`, подпись `codesign --options runtime --entitlements` — ad-hoc по умолчанию, `SIGN_IDENTITY` для Developer ID.
- **`scripts/release.sh <ver> [--unsigned]`:** при наличии Developer ID — нотаризация и staple приложения, DMG (`hdiutil`, UDZO, ярлык /Applications), подпись/нотаризация/staple DMG, проверка `spctl`; результат — `dist/Subus-<ver>.dmg` и `dist/Subus.dmg`. Без Developer ID — `--unsigned`.
- Комментарии в скриптах — на русском, как в соседних проектах.

## 13. Процесс

- `git`: `main` — релизы, `develop` — интеграция; работа в `feature/*`, `fix/*`, `docs/*`, `chore/*` от `develop`, слияние `--no-ff`; теги `vX.Y.Z`.
